# Test Results

## What Works

- Artists created or matched correctly. 
- Total Estimated Miles always set correctly
- Tour Days always set correctly (start + end dates)
- Deadhead days always set correctly
- Vehicle assignments always set correctly -- coaches and trailers match perfectly
- Import matches long term vs short term correclty
- Status mapping works correctly, although we may have an opportunity to Improve process around this. 

## What Doesn't Work

This is the macro view of issues; Review "Per Quote Reporting" below for detail.

- Notes on StarTracker quotes don't transfer to anything in Bravo. Data suggests Leasing uses this for internal notes; as such, we should add content from StarTracker Notes field to a entity_note row associated with the appropriate quote in Bravo.
- Main Driver Overdrives (tour level detail) is not set based on StarTracker data.
- Automatic line item generation adds items not present in StarTracker quotes
- Rates inconsistently updated from pre-populated values in Bravo
- Quantities inconsistently updated from pre-populated values in Bravo
- "Co-Driver Per Diems" line item not used appropriately when Co-Driver Days are present on a quote, making the "Per Diem" amount mismatch on some quotes

## Updated Quote Item Types since Import

Since running this import, we updated a few quote item types to better match Leasing's needs: 

- "Generator Services" became "Weekly Generator Services" and is a short-term only line item. It is not needed as an automatic line item for long-term quotes, as it is never quoted for those leases. 
- "Weekly Trailer Wash" was updated to a prepopulated $40 rate
- "Bus Washes" was renamed to "Weekly Coach Wash"

## Identified Process Improvements
- [ ] **Create a Total Matching Query** Ultimately, the easiest way to test the results of an import of quote data is to compare the calculated total from Bravo to the Total recorded in the StarTracker data. If the totals on a Quote do not match the equivalent Total for a Tour in StarTracker, odds are something didn't map correctly. Ideally, we'd update our process so that we can run a query and create a report -- showing how many Totals match between the two, and how many don't. A list of those that don't match would enable me to more quickly go evaluate when/where differences occur. 
- [ ] **Move Status Mapping To a Post-Review Step** In cases when manual adustments need to be made, the Quote Status can become an issue in Bravo. "Declined" quotes are locked and cannot be edited without violating the data constraint. We either need a way to remove the status temporarily, or our process needs to allow for the 1) import and creation of quotes, 2) checking of totals against StarTracker data (see above) in order to spot issues or manual tweaks needed, 3) the updating of quote status in Bravo to match StarTracker status.
- [ ] **Better Populate New Artist Records + Contact Records Using StarTraker Data** Nice to have, but when creating Artist records it would be ideal to setup these new records usign the Name, Address, City, State, and Zip info from StarTracker (columns H - N). Additionally, we have Contact records in the StarTracker data (Columns O - V) that would ideally create Contact records, and allow us to build Artist <> Contact joins.
